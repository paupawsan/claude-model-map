02スレッド単位Per thread会話が続くときに効いてくることwhat matters once it's a conversation
  1. effort はスレッド開始時に決めて、途中で変えない。 effort はリクエスト単位の設定なので次のリクエストから変えられますが、同じ会話の中で深さが変わると、ターンごとに挙動が揺れます。振り分けるならワークロード単位で。 Pick effort at the start of a thread and hold it. It's a per-request setting so you can change it on the next call, but swapping depth inside one conversation makes the behaviour inconsistent from turn to turn. Vary it across workloads, not within a thread.
  2. モデルを上げるときは、履歴ごと持ち上げない。 長いスレッドをそのまま上位モデルに流すと、毎ターン全履歴が入力課金されます。要点を要約して新しいスレッドで上げるほうが安く、精度も落ちません。 Escalating? Don't drag the history up with you. Piping a long thread into a bigger model re-bills the whole transcript every turn. Summarize and start a fresh thread at the higher tier instead.
  3. 長いスレッドは compaction / context editing で畳む。 会話が伸びるほど毎ターンの入力が増えます。一般利用なら、話題が変わった時点で新しいチャットを始めるのが最も効きます。 Fold long threads with compaction or context editing. Input grows every turn a thread runs. In general use the simplest version is: new topic, new chat.
  4. 運用上の変化はユーザー発話に混ぜない。 ファイルが変わった、権限が変わった、ツールが増えた——こうした事実は mid-conversation system message として入れます。 Don't smuggle operator facts into user turns. Files changed, permissions changed, tools added — send those as mid-conversation system messages.
  5. キャッシュの最小長を確認する。 キャッシュ可能な接頭部は Opus 5 と Fable 5 で 512 トークン、Sonnet 5 で 1,024、Haiku 4.5 で 4,096 です。これを下回るとキャッシュされず、しかもエラーは返りません。気づかないまま通常料金を払い続けることになります。 Check the cache minimum before you count on caching. The cacheable prefix is 512 tokens on Opus 5 and Fable 5, 1,024 on Sonnet 5, and 4,096 on Haiku 4.5. Below that nothing is cached and no error is returned — you just quietly pay full price.
03ループ全体Per loop複数呼び出し・複数エージェントmany calls, many agents
  1. effort は1ステップの深さ、task budget はループ全体の幅。 両方あって初めて制御になります。output_config.task_budget に {"type": "tokens", "total": N} を渡すと、モデルは残量カウントダウンを見ながら優先順位をつけ、途中で切れずに畳んで終われます。 Effort tunes depth per step; task budget tunes breadth across the loop. You need both. Set output_config.task_budget to {"type": "tokens", "total": N} and the model paces itself against a running countdown, wrapping up cleanly instead of getting cut off.
  2. task budget はベータ。 ヘッダ task-budgets-2026-03-13 が必要で、Opus 5・Fable 5・Sonnet 5 は対応、Haiku 4.5 は非対応。最小値は 20,000 トークン。 Task budgets are beta. Header task-budgets-2026-03-13; supported on Opus 5, Fable 5, and Sonnet 5, not on Haiku 4.5. Minimum total is 20,000 tokens.
  3. 予算は「目安」であって上限ではない。 硬い上限は max_tokens のほうです。xhigh / max で回すなら max_tokens は 64k 以上を確保します。 The budget is advisory, not a cap. max_tokens is the hard ceiling. Running at xhigh or max, give it at least 64k.
  4. 予算は小さすぎるほうが危ない。 明らかに足りない値を見せると、モデルは着手を断ったり、勝手に縮小したり、早期に打ち切ったりします。まず予算なしで実測し、p99 から始めて調整してください。 Too small is the dangerous direction. Shown a budget that clearly can't cover the task, the model may decline it, scope it down, or stop early. Measure without a budget first, start at your p99, tune from there.
  5. サブエージェントは別スレッド、別 effort。 親には要約だけを返し、生ログは戻さない。オーケストレーターが持つのは計画と契約だけにします。 Give each subagent its own thread and its own effort. Return summaries to the parent, never raw logs. The orchestrator holds the plan and the contracts, nothing else.
  6. セッション全体で起動するサブエージェント数に上限を置く。 1回の呼び出しごとではなく、セッション累計で数える。暴走した計画がクォータを食い尽くすのを止められるのはここだけです。 Cap total subagents per session, not per call. Counting cumulatively across the session is the only place a runaway plan can be stopped before it eats the quota.
  7. 降格の順序を設定に書く。 Fable 5 → Opus 5 → Sonnet 5。API では降格は自動ではなく、fallbacks パラメータなどで明示的に有効にする必要があります。あわせて、実際に応答したモデルをログに残します。フォールバックされたターンでは、レスポンスの model フィールドは要求したモデルではなく実際に応答したモデルを返します。 Put the fallback ladder in config. Fable 5 → Opus 5 → Sonnet 5. Nothing steps down on its own — on the API you have to enable it, via the fallbacks parameter or your own retry. Log which model actually answered: on a fallback-served turn the response's model field reports the model that served it, not the one you asked for.
04effort の 5 段階The five effort levels
low

速度と費用が最優先。分類、簡単な検索、サブエージェント。ツール呼び出しも減り、前置きなしで動きます。 Speed and cost first — classification, quick lookups, subagents.It also makes fewer tool calls and skips the preamble.

medium

バランス型。費用を抑えつつ十分な性能が要るとき。Sonnet 5 では既定からの素直な節約段。 Balanced — solid results without the full token spend.On Sonnet 5, the clean cost step-down from default.

high

既定値。 複雑な推論、難しいコーディング、エージェント処理。指定しないのと同じ挙動。API と Claude Code の初期値。 The default. Complex reasoning, hard coding, agentic work.Identical to omitting the parameter. This is what the API and Claude Code start at.

xhigh

30 分を超える長丁場のエージェント／コーディング。Fable 5・Opus 5・Sonnet 5 で利用可。max_tokens を大きく取ること。 Long-horizon agentic and coding runs past 30 minutes.Available on Fable 5, Opus 5, Sonnet 5. Pair it with a large max_tokens.

max

制約なしの最大能力。最も深い推論が要る場面だけに。Haiku 4.5 は effort 自体に非対応。 Maximum capability, no constraints on spend. Reserve it.Haiku 4.5 doesn't support the effort parameter at all.

まずここで通す。 ワーカー呼び出しがトークン消費の大半を占めます。全体を Sonnet 5 で走らせ、詰まった箇所だけ上げるほうが、最初から上位に振るより安く速く着きます。Sonnet 5 は新しいトークナイザを採用しており、同じ文章でも Sonnet 4.6 より約 30% 多いトークン数になります。単価は据え置きですが、4.6 基準で組んだ見積もりは低く出ます。導入価格 $2 / $10 は 2026年8月31日まで。 Run the pass here first. Worker calls dominate spend — run everything on Sonnet 5 and escalate only where it stalls. Sonnet 5 also ships a new tokenizer: the same text produces about 30% more tokens than on Sonnet 4.6, so per-token rates are unchanged but any budget sized on 4.6 runs low. Introductory pricing of $2 / $10 runs through August 31, 2026.

xhigh / max では thinking を無効化できません（400 エラー）。その帯で回すときは max_tokens を 64k から。なお effort を上げても返答が長くなるだけで短くはなりません——短さが要るならプロンプトで指定してください。4系から設定を引き継がず、evals で振り直しを。知識が最も新しいのもこのモデルです。 Thinking can't be disabled at xhigh or max — those requests 400. Start max_tokens at 64k there. Effort also won't shorten replies on Opus 5, so prompt for length instead. Don't carry effort settings over from 4.x models; re-sweep them. It also has the most recent knowledge of the four.

まず effort を下げてみる。 Fable 5 では effort が知能・遅延・費用の主要なつまみです。思考は常時オン。提供状況はプランと地域で異なります。API では、拒否はエラーではなく HTTP 200 と stop_reason: "refusal" で返るため、content[0] を前提にしたコードは壊れます。別モデルでの再試行は任意で、fallbacks パラメータ、SDK ミドルウェア、または自前の再試行のいずれかを使います。ドキュメント上のフォールバック先は Opus 4.8 です。また Fable 5 は 30 日間のデータ保持が必要な Covered Model のため、ゼロデータ保持（ZDR）では利用できません。ZDR の組織は、特定のワークスペースで 30 日保持を有効にし、そこ経由で使う必要があります。 Try stepping effort down first. On Fable 5, effort is the primary dial for intelligence, latency, and cost. Thinking is always on. Availability varies by plan and region. On the API a declined request is not an error: it returns HTTP 200 with stop_reason: "refusal", so code that reads content[0] breaks on it. Retrying on another model is opt-in — the fallbacks parameter, SDK middleware, or your own retry. The documented fallback target is Opus 4.8. Fable 5 is also a Covered Model requiring 30-day data retention, so it is not available under zero data retention: a ZDR organization has to enable 30-day retention on a specific workspace and route Fable 5 traffic through it.
